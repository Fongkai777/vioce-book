# 部署与运维检查清单

[English](OPERATIONS.md) · [中文项目首页](../README.zh-CN.md)

## 支持的部署方式

当前部署目标是 Sites 托管的 Cloudflare Workers，使用名为 `DB` 的 D1 绑定。`.openai/hosting.json` 指向现有站点，不应给无关 fork 复用其身份。GitHub 保存源码与检查工作流，**不托管网站、密钥或私人书库；push 不等于部署**。

使用 Node.js 24 和 pnpm 11.25.0，执行 `pnpm install --frozen-lockfile`，不得悄悄改变锁文件。`pnpm check` 包含发布扫描、类型、lint（零警告）、离线测试和 Worker/客户端构建，不需要模型凭据。实际运行的模型调用另行配置。

## 首次本地启动

首次初始化前，应选择非公开的 `ADMIN_USERNAME`，不要沿用示例 admin，并设置长随机密码。之后改变量不会重命名旧账号，可能创建另一个管理员；本次修改不会自动改动现有账号。

发布后请求 `/api/health`，检查 Worker 日志中的 `auth_client_ip_status` 是否为 `status: cloudflare`、`usable: true`，日志不记录真实 IP。这只证明被测请求链路可用，不代表所有代理/客户端。线上头缺失、无效或为 Cloudflare Worker 共享地址时，会告警且登录/注册返回 503；应修复平台可信 IP 转发或回滚，不能用全站 local 桶或信任客户端转发头掩盖问题。参见 [Cloudflare 请求头语义](https://developers.cloudflare.com/fundamentals/reference/http-headers/)。health 响应仍代表数据库就绪，IP 日志是独立运维检查。

管理员仍受 IP/组合限流，但不受普通账号跨 IP 锁定；已登录管理员的二次验密单独计数。这提升可用性，但不防分布式猜密码，全面开放仍需 MFA/边缘防护。

1. 按 README 复制空模板为 `.env.local` 并配置，仅本地保留，不提交。
2. 执行 `pnpm db:migrate:local`，按 `wrangler.local.jsonc` 将已提交 SQL 迁移应用到 `.wrangler/state`；重复执行跳过已记录迁移，不使用 `--remote`。
3. `pnpm dev` 后用初始化管理员登录，创建普通测试账号。
4. 打开示例、查看内容和建议问题。真实提问产生模型费用，麦克风测试必须获得操作者同意。

本地 D1 ID 是模拟器占位，不是生产配置。若旧库曾手动执行 SQL，应先核对迁移历史并保留原数据，不能通过清空数据“修复”迁移。

## 发布步骤

1. 保留一个已知正常的 Sites 版本，记录当前提交、部署 ID 和迁移集合。
2. 对目标源码运行检查、审阅 diff 和依赖告警。模式扫描不等于完整安全审计。
3. 配置服务端 `OPENAI_API_KEY`、`ADMIN_USERNAME`、`ADMIN_PASSWORD`，必要时配置旧索引查询凭据。不得放入 `NEXT_PUBLIC_*`、工作流、public 或发布归档。
4. 使用 Sites 支持的源码同步、构建、打包、保存版本、部署流程，保持站点受众和 D1 绑定不变。归档须对应同一提交，先审核迁移再发布。
5. 等待最终部署状态，验证登录、普通额度、示例书、引用定位和管理权限。`/api/health` 检查配置、D1 可达与表就绪，不付费调用供应商，不能证明模型当前可用。
6. 记录实际冒烟测试结果。CI 无生产凭据，也不负责部署。

## 回滚与恢复

- 代码回滚是重新部署已保存的正常 Sites 版本，不是强制推送 Git 历史。
- 代码回滚不会撤销 D1 迁移。优先增量、向后兼容变更；破坏性迁移前下载并验证备份。删除的数据不会因旧 Worker 恢复。
- 管理后台 **Encrypted server backup & restore** 只备份服务端数据，按[备份说明](BACKUP-RESTORE.zh-CN.md)操作。CI 的恢复演练使用合成数据库，不是生产恢复或 SLA 证明。
- PDF、索引和聊天在浏览器。通过 **Book management → Backup & restore** 逐书导出；服务端备份不能恢复这些内容。未启用自动或云端备份。
- 偏好和主动反馈在 D1；反馈含问答且管理员可读，不能把全部用户数据都描述为仅保存在浏览器。

## 凭据与账号

初始化管理员仅在用户名不存在时创建。更改托管配置中的 `ADMIN_PASSWORD` 不会轮换已有数据库密码。当前无自助找回或 MFA；账号恢复与密码轮换需要受审查的维护操作，更新密码哈希并撤销会话，绝不能把明文密码写入 D1，也不要把管理员账号交给面试官。

怀疑模型 key 泄漏时先撤销，再更新托管 secret、做受控验证并核对账单。仅删最新提交中的密钥不能清除历史。仓库所有者应自行在 GitHub 启用 main 分支保护与必需检查；工作流不会替你修改权限设置。

## 监控

管理员面板展示就绪状态、当天预算、已接受供应商请求、请求/错误数量、各路由状态的平均及最大延迟和控制面审计。覆盖登录及六类 AI 接口，不覆盖全部静态资源和 API。

预算预留达到 80%，或至少五个请求中 5xx 达到 10%，面板会警告。需要手动刷新，未启用定时检查、告警投递或值班 SLA。指标只含路由、状态、次数、延迟和时间，不含提示、音频或密钥；超过 30 天的聚合在刷新面板时惰性清理，全局费用和控制面审计保留。未知异常仅写安全的路由、状态、请求 ID，可用 `X-Request-Id` 对照。

## 费用与请求限制

全站默认每天 US$5，按新加坡日期重置。管理员可调 US$0–100、设置 1–8 个全局并发请求（默认 4）或暂停新的 AI 请求；已接受请求可能完成。每账号最多两个在途供应商请求。预算更新和租约插入同事务，租约 180 秒过期，上游请求及响应读取最多 120 秒。缺少 D1 控制表时拒绝调用；调低预算不清零已花费，失败或打断没有有效 usage 时保留估算。

v2 对已知官方 OpenAI 模型按 token 预留和结算；管理员可区分已结算、估算/待处理及旧/恢复费用。二进制 TTS、未知模型、代理和旧通义路径仍有估算。部署不重置已有总额。详见[费用计算](PRICING.zh-CN.md)，应用保护不是供应商硬限额，尤其不能约束共用 key 的其他程序。

请求体读取时即限制大小，不依赖可信 Content-Length：

| 接口 | 请求体上限 |
| --- | --- |
| answer | 450 kB |
| embed | 3.2 MB |
| OCR | 8.01 MB |
| multipart 转写 | 6.5 MB |
| speech | 40 kB |
| summary | 32 kB |
| login | 4 KiB |

上游响应体最多 16 MB。这些应用级限制不是边缘 WAF 或完整分布式拒绝服务防护。

每日默认个人额度为 20 次提问、600 秒语音输入，可按用户覆盖；其他保护为索引 750,000 字符等价单位（OCR 每页预扣 10,000）、合成语音 50,000 字符、查询向量为提问上限的两倍、历史维护 500,000 字符且单次至少 1,000 单位。已接受的工作在供应商请求前计入，失败或打断不自动退款。

## 全面开放前的检查项

以下是未完成的决策或验证，不是既有保证：

- 测量真人、不同设备和浏览器的识别、回声、打断与延迟，执行负载/长时间运行测试及[人工证据基准](EVALUATION.zh-CN.md)。
- 增加纯键盘自由提问入口，完成无障碍审计；现有建议问题和转写编辑不等价于完整替代。
- 自动异地备份与外部告警目前按要求禁用；手动导出不等于备份计划或恢复 SLA。
- 定期对照供应商账单，模型升级时审查费率。转写已按规范 PCM WAV 校验真实时长，但 TTS 和未知供应商仍是估算。
- 添加部署侧 WAF/边缘限流；现有并发和费用保护不构成全面暴力破解或 DDoS 防护。
- 为目标受众确定数据保留删除、反馈同意、模型隐私与事件响应；评估更强密码 KDF、MFA 和恢复流程。
- 定期审查依赖，特别是 beta Vinext。构建成功不是安全或可用性认证。

满足这些条件前，应仅向已知评审者开放凭据，并保持供应商侧支出限制较低。
