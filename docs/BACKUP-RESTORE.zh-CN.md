# 手动备份与恢复

[English](BACKUP-RESTORE.md) · [中文项目首页](../README.zh-CN.md)

当前没有自动任务或云端备份存储。重要变更前先下载并核对备份，保存在仓库之外，最好放在另一台加密设备。使用长随机口令并与文件分开保存，应用不记住口令；丢失口令不能恢复加密文件。

## 服务端快照

1. 管理员打开 **Health, budget & recovery → Encrypted server backup & restore**。
2. 输入 12–256 字符备份口令及当前管理员密码，点击 **Download server backup**。服务器重新验密，读取一致 D1 快照并加密后经 HTTPS 返回，不调用 AI，也不暂停网站。
3. 快照包含账号与密码哈希、每日用量、额度覆盖、偏好、主动反馈及全局费用总额；不含会话/登录尝试、API key、部署配置、监控审计、本机书籍或聊天。这是应用快照，不是物理 D1 导出或时间点恢复。
4. 检查文件确实下载并妥善保存；审计中的“已下载”事件不能证明你已把文件安全备份。

### 恢复会替换数据

**不要为了验证备份而向生产数据库执行恢复。**

1. 先下载一份当前服务器安全副本。
2. 点击 **Pause AI now**，等待在途请求结束；仍有有效租约时拒绝恢复。
3. 选择备份，输入其口令、当前管理员密码，以及 `RESTORE SERVER DATA`，确认替换警告。
4. 服务端验证权限、版本、表列白名单、账号关系和大小后，在一个 D1 事务中替换应用表；SQL/约束失败会回滚替换与会话撤销，事务内再次核验维护前提。
5. 成功后所有会话失效。使用快照中存在的管理员及其**备份时的密码**重新登录。AI 保持暂停；费用按 `MAX` 合并，不降低现有总额，当前预算/并发设置和审计保留。
6. 检查账号数量、代表性偏好与反馈及 `/api/health`，确认后显式恢复 AI。恢复出错时用安全副本回滚数据，不强推 Git 历史。

全新 D1 实例需要先应用迁移、配置运行 secret 和初始化管理员，再登录、暂停、恢复。key 和托管配置另行恢复；快照保留账号 ID，以便同源浏览器书库继续关联。若当前实例没有管理员可登录，此界面不是紧急绕过入口；应由托管运维人员建立新实例，不能增加公开恢复端点。

每表不超过 10,000 行或 1.5 MB UTF-8 JSON，总明文不超过 4 MB，加密数据不超过 6 MB（HTTP 封装 7 MB）。超限会报错而不静默截断；更大规模需审查后的托管 D1 导入导出。格式 v1 需要匹配应用表结构，不自动跨版本转换。

## 本机书籍与对话备份

1. 打开 **Book management**，选书并展开 **Backup & restore**。
2. 输入备份口令，点击 **Download selected book**。包含该账号该书可用的原 PDF、元数据、全部已存文字、分段、向量、已存对话和摘要缓存；未保存的内存对话和已删书的历史不包含。每本书单独操作，不联网或重建向量。
3. 换浏览器恢复时，登录**同一个账号**，选择文件并输入口令，成功后刷新。其他账号备份会拒绝；重建同名账号但 ID 不同，也不是原账号。
4. 不覆盖已有的不同索引，现有对话和摘要优先。书和历史写入是不同 IndexedDB 事务，可能书已恢复而历史待重试；重复恢复同一文件安全且不复制消息。备份与恢复时关闭其他标签页，避免同时修改数据。

本机备份限制：PDF 不超过 35 MB，明文书籍快照不超过 50 MB，加密文件不超过 75 MB。处理在内存完成，大库应逐本备份，超限书另存原文件。备份不授予跨账号访问，也不是自动同步。

## 已验证与未验证

离线合成账号和隔离 SQLite/IndexedDB 测试覆盖加密往返、随机盐/nonce、错口令、篡改、未知格式、账号隔离、向量/PDF/历史保留、重复恢复、权限/跨站/重新验密、在途请求拒绝、事务回滚、撤销会话和全局费用保留。测试不覆盖真实生产数据。

实际恢复时长、最大规模性能、异地备份流程和生产恢复 SLA 仍由运维人员验证。
