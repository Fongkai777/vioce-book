# 架构与设计决策

[English](ARCHITECTURE.md) · [中文项目首页](../README.zh-CN.md)

## 端到端流程

```text
PDF
  → 浏览器 PDF.js 按页提取文字
  → 扫描或少文字页面：本机渲染 → /api/ocr → 视觉 OCR
  → 识别章节标题与结构
  → 保留页码的重叠分段
  → /api/embed → text-embedding-3-small
  → IndexedDB 保存 PDF、元数据、文字和索引

麦克风
  → AudioWorklet 检测说话 → 16 kHz 单声道 PCM WAV
  → /api/transcribe → 语音转写
  → 查询 embedding
  → 语义排名 + BM25 关键词排名
  → RRF 排名融合 → 多样性筛选
  → /api/answer → 带 [S#] 引用的回答
  → /api/speech → 语音合成 → 浏览器播放
```

模型接口先验证网站的 HttpOnly 登录会话。D1 保存账号、密码哈希、会话、按新加坡日期统计的用量和管理员设置的个人额度。条件更新以原子方式检查剩余额度，避免并发请求使用同一份余额。

## 后端控制面

`lib/operations.ts` 包装六类付费 AI 接口，执行鉴权、请求体字节限制和仅元数据指标采集。供应商适配器在同一 D1 事务内预留美元微单位预算并取得全站及用户并发租约，读取响应完成后在 `finally` 释放租约。

已知模型的成功响应如果包含有效 token usage，会对原请求日期的预留进行原子、幂等结算。失败或缺失 usage 保留估算；`operations_costs` 只保存模型、策略、token 和费用等元数据。缺少控制面表时拒绝调用，而不是跳过预算。详见[费用计算](PRICING.zh-CN.md)，这些控制不是供应商账单或边缘 WAF。

`lib/server-backup.ts` 对允许的应用表做一致性快照，`lib/backup-crypto.ts` 生成 AES-GCM 加密封装。密钥和会话令牌不进入备份。管理员重新验证密码后，恢复在一个事务内替换应用数据，保留控制面，并确保全局费用不降低。本机书籍使用同类加密封装，但导出过程不离开设备，且校验账号所有权、保护已有书和历史。两种备份都是手动操作，见[恢复说明](BACKUP-RESTORE.zh-CN.md)。

## 为什么在浏览器处理与保存书籍

浏览器处理让原 PDF 无需存入应用服务器，也省去了原型阶段的上传存储生命周期管理。每本 PDF、文字分段和向量按登录账号保存于 IndexedDB，再次选书直接恢复索引。

普通 PDF 的提取文字会发送到 embedding 接口。缺少文字的页面则在本机渲染成有大小限制的 JPEG，再发送到 OCR 接口。因此“本机保存”不代表不经过云端模型。代价是私人书库不会自动跨设备同步，大书库占用浏览器空间。

未来若提供同步产品，可把入库改为异步任务，使用租户隔离的对象存储和向量数据库；这些不属于当前已实现能力。

### 轻量列表与存储迁移

IndexedDB v2 将数据分为三个存储区：

| 存储区 | 内容 | 何时读取 |
| --- | --- | --- |
| `books` | 所属账号、书 ID、标题、统计、模型、维度、时间 | 列表与元数据更新。 |
| `book-content` | 文字与向量 | 选书或检索。 |
| `book-files` | 可选原始 PDF | 需要预览或导出时。 |

列表不读取完整索引或 PDF，更新最近打开时间也只写元数据。v1 升级在单个升级事务中逐条转换，失败则回滚。三个存储区使用相同的账号隔离键，删除书籍时原子删除对应书数据。

旧 Counseling Copilot 迁移保留版本化 JSON 的维护导出与校验代码，但公共导入 UI 已移除。校验检查模型、维度、ID 和向量有限值。旧索引使用 `text-embedding-v4` 的 1024 维向量，新上传 PDF 使用 `text-embedding-3-small` 的 1536 维向量；旧模型接口只允许一次查询，不接受重新索引请求。迁移无需把整本书或向量发给模型；对话时才发送查询和检索摘录。

查询额度独立于 OCR 和书籍索引，避免索引额度耗尽后无法使用已存书。查询最多 2,000 字符，需有提问余额并原子消耗一次查询额度；每日搜索上限为个人提问上限的两倍，以容纳重试。回答仍单独扣提问额度。

## 检索策略

### 先结构后长度

把页面文字转换为行，识别可能的章、部分、节标题，在逻辑章节内构造有少量重叠的段落，保留章节标题和页码范围。相比全书机械按固定字符数切分，这样更容易保留语义边界及可读引用标签；处理仍是可离线测试的确定性逻辑。

### 混合召回与排名融合

语义相似度用于问题与原文措辞不同的情况；BM25 用于人名、术语、编号和精确措辞。RRF 使用各自排名融合，避免为不同分数尺度设置脆弱的归一化规则。随后通过词汇冗余惩罚筛除过于相似的候选，避免上下文被重复片段占满。

### 有依据的回答

证据标注为 `[S1]`、`[S2]` 等，提示要求模型仅凭摘录回答、为事实提供引用、证据不足时明确说明。来源卡片与页码从实际段落生成，不采信模型编造的页码。格式正确不代表语义一定有依据，仍需人工质量评估。

## 安全与失败处理

- 凭据仅在服务端；私人运行文件和产物不进入 Git 或发布包。
- 账号过滤是逻辑隔离，不防掌握本机浏览器与开发者工具的人读取存储。
- 使用带随机盐的 PBKDF2-SHA256 密码哈希、哈希后的 256 位随机会话令牌；HTTPS Cookie 为 HttpOnly、Secure、SameSite=Lax，有效期七天。
- 跨站修改请求在解析前拒绝；异常仅返回允许公开的信息，不透传供应商响应体。
- 偏好和显式反馈保存在 D1。反馈包含该轮问题与回答，管理员可见；这不等于自动同步全部聊天。
- 图片页尝试 OCR；成功识别但仍无文字的页不会参与索引，整份无可读内容会报错。OCR 请求失败会明确报告。
- 麦克风拒绝授权时显示错误，仍可用建议问题；没有通用文本输入框，异常未发送转写可以编辑。
- 空转写保留已有文字，真实转写失败进入待确认状态。已接受请求即使失败或被打断也可能消耗额度。
- TTS 失败不删除已经生成的文字回答。

完整边界见[安全说明](../SECURITY.zh-CN.md)与[API 说明](API.zh-CN.md)。
